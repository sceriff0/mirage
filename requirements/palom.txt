# A COMPLETE PIN FILE THAT TAKES NO constraints.txt, and why. PALOM's own package metadata
# (PyPI palom==2026.4.1, requires_dist [FULL]) asks for `scikit-image>=0.18,<0.20` and
# `tifffile<=2024.7.2`; requirements/constraints.txt pins scikit-image 0.25.2 and tifffile
# 2025.5.10, so the two cannot be installed together. scipy and dask follow PALOM's side
# for one reason each, given beside them. The divergences are recorded in
# tests/test_container_harmonisation.py's PINNED_EXCEPTIONS. Python is 3.10: PALOM
# requires >=3.10, and scikit-image 0.19.3 publishes no wheel for 3.11 or later.
#
# EVERY name the resolver installs is pinned below (62 of them), not only the ones
# PALOM names, so a rebuild cannot move a version under the benchmark. The set was resolved
# on 2026-10-10 from PyPI metadata for CPython 3.10 on linux x86_64, twice, and the two
# agree name for name: `uv pip compile --python-version 3.10 --python-platform
# x86_64-manylinux_2_28` (uv 0.12.13) and `pip install --dry-run --report` (pip 26.2.1,
# --platform manylinux*, --only-binary=:all:). NOTHING HERE WAS INSTALLED OR IMPORTED on
# the machine that wrote this file; containers/palom/smoke.sh is where the stack first runs.
#
# stare-registration is NOT in this file. The benchmark reads images through
# stare.slide_io and stare.ome, and STARE's metadata requires scikit-image>=0.24, which
# PALOM forbids. The Dockerfile therefore installs STARE's one pinned line (taken out of
# requirements/stare.txt, so the version is still written once) with --no-deps. At v1.2.1
# stare/__init__.py imports nothing, stare/slide_io.py imports numpy (and tifffile, zarr
# inside its functions) and stare/ome.py imports tifffile: all three are pinned below.
