Supplementary Figure S6 · accuracy measures

Four registration-accuracy numbers this pipeline reports — two scored by the transform's own features, two independent, and none of them a ground truth

S1 · pipeline S2 · registration S3 · quality control S4 · lazy reads S5 · coarse alignment S6 · accuracy measures

Every registration run in this pipeline can emit up to four distinct accuracy-shaped numbers, produced by different processes, in different units, at different QC levels. Nothing in the source states which of them may be read as evidence that a registration is correct. This figure names all four, draws which ones share their input with the transform that produced them, and states plainly that none of them is checked against an externally-verified correspondence.

a

The naive expectation — "the pipeline reports a registration error"

A reviewer reading one QC JSON sees a small, well-labelled set of numbers and reasonably expects them to describe one thing. They describe four different things, and they disagree with each other by design — not by bug.

one slide-stage, four numbers — three read verbatim from the worked example in docs/registration_qc.md (lines 174-177); the fourth has no documented worked example and is left blank

None of these four is "the" registration error. The first has no documented worked value to cite at all — a fact worth sitting with on its own. The second is WARP_SEG_QC's own centroid residual, reported in both units the same JSON carries. The third is a Dice-like overlap bounded by how well two independent segmentation runs agree in the first place, not only by registration. The fourth is a diagnostic about the pairing itself — how many segmented cells got matched at all — not about the transform's accuracy. Panel b names what each one is actually computed from; panel c is why the distinction between the first and the rest matters.
b

The four measures, and what each is computed from

All four are emitted per moving slide; none of the first two is gated by reg_qc — a registration method always reports its own intrinsic error, regardless of QC level. The last two exist only at reg_qc = 2.

measurecomputed fromunitproduced byreg_qc
intrinsic TRE VALIS: its own keypoint-match residual after the fit (*_summary.csv, the "rTRE" table). STARE: the DISK+LightGlue anchor's RANSAC residual plus the per-tile phase-correlation shift (*_tre.json). px REGISTER / TILED_SOLVE always — part of registration itself
STARE confidence gate Normalised phase-correlation error, [0,1], per tile — the same measurement that decides whether a control point enters the mesh. Only the resulting accept/reject flag and tre_rigid land in *_tre.json; the raw confidence number itself is not published. unitless [0,1] TILED_REG_TILE (measures) / TILED_SOLVE (gates) always — STARE method only, not QC-gated
cell displacement Median/p90/max centroid distance between the same nuclei, warped through each registration stage, paired once at the rigid anchor. µm when a pixel size resolves (typically VALIS); px otherwise (typically STARE — the pipeline never passes a pixel size to this step on that path) WARP_SEG_QC 2
seg-QC IoU / dice_matched Per-pair IoU over the same warped, fixed-paired nuclei; dice_matched is the areal Dice restricted to those matched pairs only. unitless [0,1] WARP_SEG_QC — same JSON, same process, as cell displacement 2
c

Circularity — the load-bearing panel

Two of the four measures are computed from the same features the registrar optimised against; the other two are computed from an independently segmented signal the registrar never saw.

circular — same features the registrar fit
intrinsic TRE↺ self-scored
The registrar reports its own residual on the very correspondences it used to solve for the transform. A transform that overfits a handful of bright, easy-to-match points can report an excellent intrinsic TRE while the rest of the tissue — everything the matcher did not key on — is untouched.
STARE confidence gate↺ self-scored
The same normalised phase-correlation error is used both to decide which control points enter the mesh and as the only quality signal about how well that tile matched. Measured, not hypothetical: a tile that is roughly 40–90% off-tissue is ACCEPTED with a WRONG recovered shift, in every one of 12 swept geometry/seed configurations, injecting a bogus displacement of up to 131 px — and the range gate cannot catch it, because 131 px is well inside the default max_disp of 256 px (reg_tiled_halo).
independent — a signal the registrar never saw
cell displacementindependent input
Nuclei are segmented on each slide's native, pre-registration image by the run's own segmenter — a different algorithm, working from cell morphology, that never sees the registrar's keypoints or its optimisation target.
seg-QC IoU / dice_matchedindependent input
Computed on the exact same warped, fixed-paired native-segmentation polygons as cell displacement — a second summary of the one independent signal this pipeline has, not a second independent measurement.
What this means for reading a report. An excellent intrinsic TRE and an excellent confidence-gate pass rate say the registrar is happy with itself. They say nothing about whether the cells the registrar was never shown actually landed on top of each other. Cell displacement and dice_matched are the only two numbers in this pipeline that can contradict a registrar that is quietly wrong.
d

The correlation, and what a divergence means

GENERATE_QC_REPORT plots every slide-stage's intrinsic TRE (the circular measure) against its cell displacement (the independent one) on log-log axes, with a shaded agreement band at a fixed divergence ratio.

x-axis
intrinsic TRE
The registrar's own self-reported residual for that stage — VALIS's rigid_D/non_rigid_D column, or STARE's coarse_tre_px/refined p50.
y-axis
cell displacement
The same stage's WARP_SEG_QC centroid-residual p50 — the independent measure.
the band
3× either way
A slide-stage is called divergent when the larger of the two numbers exceeds 3× the smaller — a symmetric rule, drawn as two lines parallel to the identity on the log axes rather than recomputed per point.
Reading a point off the band. A slide-stage whose cell displacement is much larger than its intrinsic TRE is a registrar reporting a small residual on its own features while the independently segmented tissue disagrees — either the transform genuinely failed somewhere the registrar's features never sampled, or the independent segmentation/pairing itself produced an artefact; the reconciliation cannot tell the two apart by itself, only flag that they disagree. A slide-stage whose intrinsic TRE is much larger than its cell displacement means the tissue-level correspondence is actually fine despite a poor self-reported feature fit — the keypoints the registrar had to work with were sparse or noisy in a way that did not carry through to the cells. A point inside the band means the two measures corroborate each other, which is the only case in which either one, alone, would have been a reasonable thing to trust.
a labelling caveat in the reconciliation itself The reconciliation's own output fields are named feature_tre_um and cell_disp_um regardless of what unit the numbers are actually in. The cell-displacement side is genuine µm only when a pixel size resolved (the VALIS-typical case) and is otherwise the raw px value under a µm-suffixed key; the intrinsic-TRE side is always whichever unit its own source file already reports, unconverted. The divergence ratio is unit-free by construction (it compares a number to itself scaled), so a same-unit comparison is unaffected — but a reader taking either axis label as a literal micron count should not.

The knobs

Defaults verbatim from the params{} block of nextflow.config.

reg_qc2 0 none · 1 overlay · 2 +cell-based measures. 2 is the default — the independent measure this figure argues matters most is on unless a run opts out. The ladder is a cost switch, not a capability tier: no level changes what the registration itself does, only how much of it gets measured.
reg_tiled_max_dispnull STARE's range gate — drop a window vector whose |displacement| (px) is at or beyond this; null = the read halo. (STARE v2 retired the confidence and TRE gates.)
reg_tiled_stride64 STARE's mesh resolution — one window vector per stride px (window 2×stride), solved into the mesh by robust DCT-PLS; no vector is zeroed for being small.
spatialdata_residual_join_max_px15.0 Max centroid distance (px) when spatially joining WARP_SEG_QC's per-cell residuals onto the segmentation mask for SpatialData export — a separate join, not a registration-quality knob.

Honest limits

What none of the four measures in this figure can do, stated once rather than left for a reviewer to discover per-measure.

1 — there is no ground truth anywhere in this pipeline All four measures are reference-free: they describe how well a transform's own features fit each other, or how well two independently produced signals (a registrar's transform and a segmenter's cells) agree with each other. Agreement between two reference-free signals is evidence, not proof — none of the four can say a configuration is correct, only that it is more or less internally consistent than another.
2 — nothing in this repository or its sibling branches closes that gap today No landmark TRE against ANHIR or ACROBAT correspondences was ever measured for this release. The harness that would produce one (benchmarks/registration_eval/) exists on no branch, including benchmarking; the removal record — benchmarks/README.md section B, documenting it and a synthetic-ground-truth successor also removed after it — lives only on the benchmarking branch, since main and dev carry no benchmarks/ directory at all.
3 — the question a reviewer is most likely to ask has no answer here "What is the absolute registration error, in physical units, against independently and externally verified correspondences?" This pipeline cannot answer that question for any configuration it ships. That is the fact this figure exists to say out loud, rather than leave for a reviewer to discover by reading four JSON keys and assuming one of them must be it.

Supplementary Figure S6. What each accuracy measure actually measures. (a) A registration run can emit four differently-scoped accuracy numbers per slide-stage; none is privileged as "the" registration error, and they are not required to agree. (b) Intrinsic TRE and the STARE confidence gate are emitted unconditionally, as part of registration itself; cell displacement and seg-QC IoU/dice_matched exist only at reg_qc = 2, computed by WARP_SEG_QC from nuclei segmented on each slide's native image. (c) Intrinsic TRE and the confidence gate are both scored on the same features the registrar optimised against or used to decide its own mesh; cell displacement and dice_matched are the only two numbers computed from a signal the registrar never saw. (d) Plotting intrinsic TRE against cell displacement exposes exactly the failure mode neither catches alone — a registrar that scores itself well on features that do not represent the tissue, or an independent measure thrown off by a segmentation artefact — with a fixed 3× ratio marking disagreement; the reconciliation's own output fields carry a µm-suffixed name regardless of the unit actually inside them. (e) reg_qc defaults to its richest level; STARE's two gating parameters are correctness knobs, not cost/accuracy tier knobs. (f) None of the four measures is checked against an externally-verified correspondence, nothing in this codebase currently closes that gap, and a reviewer asking for an absolute error in physical units against known correspondences has no answer here.
