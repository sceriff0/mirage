# deeperhistreg==1.0.1 has no requires_dist at all ([FULL]). The direct requirements
# below are its repository's own requirements.txt (github.com/MWod/DeeperHistReg, [FULL]),
# with two substitutions: `opencv_contrib_python` is installed as the -headless build of
# the same package (the image has no display libraries), and `openslide_python` is given
# `openslide-bin` and `pyvips` is given `pyvips-binary`, the wheels that stand in for
# system OpenSlide and libvips.
#
# torch 2.6.0 IS THE BASE IMAGE'S (pytorch/pytorch:2.6.0-cuda12.4-cudnn9-runtime), a CUDA
# build that also runs on a CPU. Upstream asks only for torch>=1.13.1; torch >= 2.3 is THIS
# BENCHMARK's floor (the adapter hands the package one-channel 16-bit TIFFs, and uint16
# arrays load into torch only from 2.3 on). The two lines below name the versions the base
# already has, so pip leaves them alone and refuses any dependency that would replace
# them; containers/deeperhistreg/smoke.sh asserts the CUDA build is still the one imported.
# In a plain virtual environment the same two lines install PyPI's default wheels.
#
# The harmonised versions hold here (nothing in the stack caps them), and STARE's
# requirements are the same lines, so `-r stare.txt` brings the imaging stack and STARE's
# one pin (the adapter reads images through stare.slide_io; imagecodecs decodes the LZW
# the package's writer saves).
-c constraints.txt
-r stare.txt
