A whole-slide multiplex image processing pipeline: modules, segmentation backends, defaults, outputs, resource model, and benchmarking

S1 · pipeline S2 · registration S3 · quality control S4 · lazy reads S5 · coarse alignment S6 · accuracy measures

A step-gated Nextflow DSL2 workflow that aligns multiplexed immunofluorescence slides, segments every cell, quantifies each marker per compartment, and exports QuPath-compatible GeoJSON, a pyramidal OME-TIFF, and a scverse-native SpatialData store. The nuclear/fiducial channel is resolved by marker name from image metadata and drives both segmentation and registration.

a

Input — the samplesheet

Every run is driven by a samplesheet CSV — no images are needed to describe the design. Each row is one image; exactly one image per patient is the registration reference (is_reference=true). Channel identity is declared metadata, never parsed from filenames.

The underlined channel is the resolved nuclear/fiducial marker. With nuclear_markers = [DAPI, CELLTOX], DAPI is used where present; the last row has no DAPI, so CELLTOX is used instead. That channel is moved to index 0 at conversion. Per-patient image counts are read from this file up front and injected into the channel metadata, so every downstream grouping streams (patient B preprocesses while patient A registers) instead of waiting for the whole cohort. A later --start reads the corresponding checkpoint CSV instead, whose columns are the ones that step requires (preprocessed_image, registered_image, or the latter plus cell_mask/nuclei_mask).

Modules and default parameters

Each lane is one step's subworkflow; boxes are processes in execution order. Chips give real defaults; chip names drop the stage prefix a parameter carries in nextflow.config (micro_reg = reg_micro_reg, max_dim = reg_max_image_dim, and every chip on the tiled fork = reg_tiled_*) — panel i gives the full names. Every process runs in a pinned container and emits versions.yml.

Why InstanSeg is the default. It is the only backend that produces a mask on a fresh clone: StarDist's configured model name is not one of the StarDist built-ins, so without segmentation_model_dir it raises FileNotFoundError, and CellSAM's weights are gated behind a DeepCell token. InstanSeg's weights are Apache-2.0 and unencumbered. It is also the only one of the three that predicts the whole-cell mask directly rather than dilating nuclei by a fixed radius — so seg_expand_distance has no effect when it is selected. An unrecognised --seg_method is rejected by name at launch rather than silently falling back to a different segmenter.

e

What a completed run leaves on disk

Per patient, under --outdir. The GeoJSON and the OME-TIFF are the primary artifacts — they are what QuPath and FlowPath open. The SpatialData store is additive: the same run, readable by scanpy, squidpy, napari-spatialdata and Vitessce without conversion. What survives is itself a parameter. At --cleanup_level final (opt-in; none is the default) the intermediates are never published at all rather than published-then-deleted, since publishDir copies and a delete would pay for a copy nobody reads. That makes none load-bearing rather than a convenience: --start and mode=add_cycle both RE-ENTER a prior run's published tree, so add_cycle is refused at launch at any other level. No checkpoint manifest is written at a cleaning level either — a manifest whose paths dangle is worse than no manifest.

The store's instance_key is the segmentation label — the only stable cell identifier the pipeline produces — so every join is keyed on it and a mismatch is fatal rather than silently positional. points/ is absent by design: this is protein imaging, so there are no transcripts to store. The pyramid is excluded from the .zarr by default (spatialdata_include_image) because writing it duplicates the largest artifact of the run. Published paths have a single owner (lib/Layout.groovy); a test asserts that every path recorded in every checkpoint CSV exists on disk and lies outside the work directory.

Resource model

Every process's cpus/memory/time has exactly one owner: a resource label or a withName: block, never both. Memory and time scale with task.attempt, so a retry after an out-of-memory kill climbs the ramp automatically, and every request is clamped to the max_* ceilings.

Retry fires on 104/134/135/137/139/140/143 (connection reset and the signal kills, including the OOM killer); anything else finishes the run. REGISTER additionally retries on exit 1, which is how VALIS reports a tile-read failure or a JVM out-of-heap. The seven QC processes are gating: they retry the whole 130–145 signal range plus 104, then finish — a broken QC task fails the run, so a green run implies a complete QC tree. Only the two opt-in evaluators above (SEG_QUALITY_EVAL, MERGE_SEG_EVAL) still fall back to ignore, and main.nf's onComplete announces a drop via workflow.stats.ignoredCount. Supplementary Figure S1. Whole-slide multiplex image processing pipeline. (a) The workflow is driven by a samplesheet in which each row is one image and exactly one image per patient is the registration reference. Channel identity is taken from image metadata; the nuclear (fiducial) channel is resolved by marker name using an ordered preference list (nuclear_markers, default DAPI then CELLTOX) and moved to channel 0 — DAPI is used where present, otherwise CELLTOX. (b) Execution is gated by --start/--stop across four ordered steps, each writing a resumable checkpoint. (c) Preprocessing standardizes and illumination-corrects images; registration aligns each moving slide to the reference through one of two interchangeable backends behind a single adapter seam — VALIS or the JVM-free tiled/STARE backend — with staged registration QC on by default and micro-registration at micro-rigid depth (reg_micro_reg=1 of 0 | 1 | 2); segmentation detects every cell on the reference and extracts morphology and contours once per mask; postprocessing quantifies each marker per compartment and exports. (d) The three segmentation backends compared on what they read, how the whole-cell mask is produced, what each requires before it will run, and how its weights are licensed — with the 17 backend-specific parameters grouped by the backend that reads them. InstanSeg is the default because it is the only one that produces a mask on an unconfigured clone. (e) Each run yields a QuPath-compatible GeoJSON and a pyramidal OME-TIFF as primary artifacts, plus an additive SpatialData .zarr that re-serializes the same masks, polygons, measurements and QC — including a per-cell registration residual — for the scverse ecosystem. (f) Each process's CPU, memory and wall-time request has a single owner and scales with the retry attempt under global ceilings; the seven quality-control processes are gating — they retry, then fail the run — and only the two opt-in segmentation evaluators are dropped rather than fatal. (g) An incremental mode folds a new imaging cycle into a completed run, reusing the prior reference, masks, and quantification. (h) A separate branch benchmarks the unmodified pipeline by parameter sweep, harvesting resource, registration-accuracy, and segmentation-stability signals from QC the pipeline already emits. No external ground-truth dataset is used. (i) Default parameters. Supplementary Figure S2 takes registration apart backend by backend; Supplementary Figure S3 does the same for the quality-control architecture summarised in (c) and (f). Parameter defaults, published paths, and resource requests are taken verbatim from the pipeline source (nextflow.config, conf/modules.config, lib/Layout.groovy) and verified against a stub run.
