# SEG_QUALITY_EVAL / MERGE_SEG_EVAL — reference-free 2D segmentation quality (CSE).
#
# Hard pins, not lower bounds. The vendored subset in bin/utils/cse/ is a COPY of upstream
# CellSegmentationEvaluator 1.5.19, so unlike a pip-installed package it does not move with its
# dependencies, and its composite QualityScore comes out of a fixed PCA model.
#
# These pins now follow tests/test_container_harmonisation.py's HARMONISED table rather than
# diverging from it. They used to be held back (scipy 1.11.4, pandas 2.2.3, tifffile 2023.2.28)
# on the argument that any bump would "shift scores across a cohort with no error". That was
# never measured, and the measurement contradicts it: tests/test_cse_equivalence.py reproduces
# tests/data/cse/golden_metrics.json exactly against scipy 1.13.1, scikit-learn 1.7.2,
# scikit-image 0.24.0 and tifffile 2023.4.12 — i.e. across a wider version spread than this
# bump — so the QualityScore is not as brittle as the old comment feared. Run that test after
# any further bump; it is what makes a real drift detectable rather than silent.
#
# COPY'd into containers/segeval/Dockerfile, and `-r`-included by requirements/ci.txt --
# so this file is also the single authority for CI's matplotlib, scikit-learn and
# xmltodict versions, which no image other than this one pins.
